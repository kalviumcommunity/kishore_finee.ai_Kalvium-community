# Document Text Cleaning Pipeline

This document details the text cleaning pipeline implemented for the `finee.ai` ingestion process.

---

## 1. Why Extracted Text Contains Noise

Text extracted from document formats like PDF, DOCX, and HTML often contains structural and encoding anomalies rather than pure raw content:
- **Layout Boilerplate**: Elements like repeated page numbers, headers, and footers (e.g., `"Financial Advisory Report"`, `"Page 3 of 12"`) are mixed directly into the body text flow.
- **Encoding Anomalies (Mojibake)**: Raw bytes are frequently decoded incorrectly during extraction (e.g., UTF-8 bytes read as Windows-1252, leading to artifacts like `â€™` instead of `’`).
- **Whitespace Issues**: Broken line endings (`\r\n`, `\r`), excessive space/tab separators, and large blocks of empty lines generated by visual padding.

---

## 2. Why Cleaning is Necessary Before Embeddings

Downstream Retrieval-Augmented Generation (RAG) uses vector embeddings to retrieve relevant context. Raw noise degrades this process:
- **Diluted Semantic Signal**: Repeated headers and page numbers inject irrelevant terms into vector embeddings, leading to poorer cosine similarity matches.
- **Wasted Token Budgets**: Layout boilerplate consumes token space in chunking windows and LLM contexts, increasing costs and reducing the useful information density.
- **Index Pollution**: Identical headers on every page make chunks from distinct parts of the document look unnecessarily similar in embedding space.

---

## 3. What the Cleaner Changes

To solve these issues, the cleaner applies the following sequential transformations:
1. **Mojibake Correction**: Replaces common UTF-8 extraction artifacts (e.g., `â€™` -> `’`, `â€œ` -> `“`, `â€“` -> `–`) safely with their correct character representations.
2. **Unicode Normalization**: Normalizes all characters using the standard NFKC (Compatibility Decomposition, Canonical Composition) algorithm.
3. **Line Ending Standardization**: Converts all Windows (`\r\n`) and Mac (`\r`) line endings to standard Unix line feeds (`\n`).
4. **Repeated Header/Footer & Page Number Removal**:
   - Detects and drops standalone page-number boilerplate (e.g., `Page 1 of 12`, `[3]`, `- 4 -`).
   - Identifies candidate headers and footers that appear consistently (frequency $\ge 50\%$ and count $\ge 2$) at the page boundaries and strips them.
5. **Whitespace Collapsing**:
   - Reduces consecutive spaces and tabs on a line to a single space.
   - Reduces consecutive blank lines ($> 2$) to a single blank line (`\n\n`) to preserve paragraph boundaries without large gaps.
   - Strips leading and trailing whitespace from the document.

---

## 4. What the Cleaner Intentionally Preserves (No Over-Cleaning)

Over-cleaning text ruins retrieval accuracy, particularly for financial and compliance search queries in `finee.ai`. The pipeline explicitly preserves:
- **Numbers and Financial Values**: Exact percentages, currencies, dates, and amounts (e.g., `$1,250.50`, `20 August 2026`) are untouched.
- **Punctuation**: Commas, decimal points, bullet markers, and brackets are left intact as they define boundaries and financial decimals.
- **Headings and Section Names**: Left unchanged, allowing hierarchical headers to be indexed correctly.
- **Casing**: Original uppercase/lowercase structures are kept intact to preserve proper nouns (names, organizations) and regulatory abbreviations.

---

## 5. Consistency Across the Corpus

The clean text output must be **100% deterministic** and consistent:
- The exact same cleaning rules and thresholds must be applied to all documents in the corpus.
- If a query is checked against the database, the query itself must be cleaned using identical rules to ensure terms match the cleaned indexed documents.

---
