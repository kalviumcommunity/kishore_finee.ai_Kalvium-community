# Similarity Search & Top-K Retrieval

This document outlines the similarity search and Top-K retrieval engine implemented for the `finee.ai` compliance-grounded financial advisory RAG platform.

---

## 1. Overview & Retrieval Lifecycle

Once the document corpus is chunked, validated, and indexed into the vector store, the retrieval phase serves as the critical grounding bridge between user questions and language model answer generation:

```
+-------------------------------------------------------------+
|                      1. USER QUERY                          |
|         "How can a learner reset their password?"           |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
|            2. SAME MODEL QUERY EMBEDDING                     |
|         text-embedding-3-small (1536 dimensions)            |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
|          3. VECTOR DATABASE SIMILARITY SEARCH               |
|            Cosine Similarity & Metadata Filter              |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
|             4. TOP-K RANKED GROUNDING CHUNKS                |
|      Score + Original Text + Source Metadata (Citations)    |
+-------------------------------------------------------------+
```

---

## 2. The 4-Step Retrieval Path

The retrieval pipeline consists of four atomic steps:

1. **Take the User Query**: The raw question or search phrase submitted by the user.
2. **Embed the Query**: Convert the query into a dense numerical vector using the **exact same embedding model** configured for the document chunks.
3. **Search the Vector Database**: Compute cosine similarity between the query vector and all candidate vectors in the collection, optionally applying metadata filtering (such as `approval_status: "approved"`).
4. **Return Ranked Chunks with Scores & Metadata**: Return the $k$ highest-scoring chunks, preserving complete provenance (`source`, `chunk_index`, `section`, `page`, `effective_date`) for downstream LLM prompt construction and statutory citation generation.

---

## 3. The "Same Model" Rule

> [!IMPORTANT]
> **Query vectors and document chunk vectors MUST be generated by the exact same embedding model.**

Vector databases perform purely mathematical distance and similarity calculations (such as cosine similarity or dot product). If document chunks are embedded with `text-embedding-3-small` while a query is embedded with a different model or dimension, the resulting vector space coordinates do not align, making similarity scores mathematically meaningless and ranking completely untrustworthy.

In `finee.ai`, this is enforced across the entire retrieval stack via `EmbeddingService` and `src.core.config.settings.EMBEDDING_MODEL`.

---

## 4. What Top-K Means & Changing-$k$ Trade-Offs

**Top-$k$** defines the number of highest-scoring document chunks returned from similarity search to serve as grounding context in the LLM prompt.

```python
results = retrieve("How can a learner reset their password?", k=3)
```

### Trade-Offs Across $k$ Values

| $k$ Value | Latency & Cost | Precision vs. Recall | Context Window Footprint | Best Used For |
| :--- | :--- | :--- | :--- | :--- |
| **$k=1$** | **Lowest** (minimal tokens) | **High precision, low recall**. Sensitive to single-chunk coverage gaps. | ~100–300 tokens | Direct lookup queries with unambiguous single answers. |
| **$k=3$** (Recommended) | **Balanced** | **High precision, strong recall**. Captures primary answer and supporting details. | ~300–800 tokens | Standard financial advisory Q&A and policy queries. |
| **$k=5$** | **Higher** (larger prompt payload) | **Maximum recall, lower precision**. May include loosely-related or tangential chunks. | ~800–1600 tokens | Complex multi-topic synthesis or broad exploratory queries. |

### Inspecting Extra Chunks when $k$ Expands

When tuning $k$, evaluate whether additional chunks provide genuine grounding evidence or introduce irrelevant noise:
- If $k=1$ returns the password reset OTP instructions (score: `0.9124`),
- $k=3$ includes two-factor authentication recovery steps (score: `0.8842`), adding valuable supporting context.
- $k=5$ may introduce debt fund fixed-income disclosures (score: `0.2105`), which represents unrelated context that should not be fed to the model.

## 5. Retrieved Chunk Data Structure

Each retrieved chunk preserves complete provenance:

```python
[
  {
    "rank": 1,
    "score": 0.9124,
    "source": "auth-and-access-guide.md",
    "chunk_index": 0,
    "text": "To reset your account password, navigate to the FInee.ai login portal...",
    "metadata": {
      "source": "auth-and-access-guide.md",
      "document_id": "doc_sec_001",
      "chunk_index": 0,
      "section": "Password Management",
      "page": 1,
      "approval_status": "approved",
      "effective_date": "2026-01-01"
    },
    "embedding_model": "text-embedding-3-small"
  }
]
```
